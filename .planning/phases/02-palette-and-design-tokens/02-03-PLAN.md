<task type="auto">
  <name>Task 2: Add the six gem-behaviour overrides and re-date the deploy canary</name>
  <files>_sass/_custom.scss</files>
  <action>
Append a clearly-commented section — "Six gem behaviours no token can reach" — with one rule per item and a comment naming the gem source line, so a later reader can tell an override from a design choice.

1. **`pre, code { color: var(--ink-800); }`** — gem `_sass/_utilities.scss:26` and `:47` paint both with `var(--global-theme-color)`, which on this palette renders whole blocks in link blue. That is visibly a bug and it breaks Phase 7's greyscale-blur test by letting code outweigh headings. **The accent must mean exactly one thing: this is interactive.** (The code-block *ground* comes from `--global-code-bg-color` → `--paper-200`, already re-pointed in plan 02-02.)

2. **`.card { box-shadow: none; }`** — `tailwind.css` hardcodes `.card{…box-shadow:0 2px 5px #00000029,0 2px 10px #0000001f}` as literals, not tokens. Cards are flush (`--global-card-bg-color` → `--paper-100`), so without this a card is an invisible box with a grey halo. Also neutralise `.hoverable:hover` (gem `_components.scss:56-67` adds `translateY(-4px)` plus two more black shadows): `box-shadow: none; transform: none;`. The projects page renders `.card`.

3. **`.navbar { opacity: 1; }`** — gem `_sass/_navbar.scss:11` sets `opacity: 0.95` on the whole fixed bar, fading navbar text by 5% and letting scrolled content smear through. Criterion 4's `grep -rn "opacity" _sass/` will not catch it (it is in the gem), but it is text faded by opacity and the phase goal forbids that.

4. **Heading ink.** Gem `_sass/_typography.scss:7-19` paints `p, h1..h6, em, div, li, span, strong` with one `--global-text-color`, so a separate heading ink is impossible through tokens alone. Add `h1, h2, h3, h4, h5, h6, .post-title { color: var(--ink-900); }` — specificity (0,0,1) vs (0,0,1), won on source order. **Decision (CONTEXT left this open): all six levels plus `.post-title` take the darker ink.** Hierarchy then rides on size, weight AND ink depth, which is the second lever Phase 7's greyscale-blur test needs.

5. **Body-copy link underline (GROUND-04, criterion 3).** Forced by contrast: `--accent-600` vs `--ink-800` is 2.24:1, far below the 3:1 needed for colour alone to distinguish a link.

        .post article a {
          text-decoration: underline;
          text-decoration-thickness: var(--underline-thickness);
          text-underline-offset: var(--underline-offset);
        }
        .post article a:hover { text-decoration-thickness: var(--underline-thickness-hover); }
        .post article a.btn  { text-decoration: none; }

    **Hover thickens the stroke; the colour holds** — no second accent value, nothing extra to keep in contrast, and it is the hook Phase 4's hand-drawn rule plugs into. Scope is `.post article a` exactly: navbar and footer links are outside `.post` and stay un-underlined, because position already signals clickability in navigational furniture and an underlined nav row reads as a 1997 page. The `.btn` exemption covers the CV page's `.cv-actions .btn`.

6. **`:focus-visible { outline: var(--focus-ring-width) solid var(--ink-900); outline-offset: var(--focus-ring-offset); }`** — nothing in the gem defines one. **Never `outline: none`, and never `box-shadow` alone** (it vanishes in Windows High Contrast Mode). `--ink-900` on `--paper-100` is 15.88:1 and the 2px offset puts the ring on clean ground.

Finally, **re-date the deploy canary**: change `--deploy-proof` to a value that identifies this deploy, e.g. `"2026-09-14 phase-02-tokens"`. Do NOT delete it, do NOT fold it into the token file, and do NOT "clean up" an apparently-unused custom property — STATE.md records it as deliberately retained, and plan 02-04 greps the served CSS for this exact value.

Then `npx prettier _sass --write --end-of-line auto` and re-read the added comments.
