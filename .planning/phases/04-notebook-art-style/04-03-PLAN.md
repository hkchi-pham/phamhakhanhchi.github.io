**MARK 1 — the section rule.** *Defence: it shows the reader where one group of work ends and
the next begins.*

```scss
.entry-group-title {
  padding-bottom: var(--space-2);
  border-bottom: var(--rule-hairline) solid var(--rule-500);
}
```

Comment: structural, so `--rule-500` and **not** the decorative `--rule-200`; the same idiom
already shipped on `.subject` at `:114`, deliberately, because repetition reads as a system.
Also record the scope decision: `.entry-group-title` reaches **three** pages (Academics,
Research, Activities); scoping to `h2` would reach five and pull the home page in, which
**Phase 6 owns**. Further Reading and CV have no `h2` at all and therefore carry no mark —
that is the honest consequence of "every mark names the content it serves", not a miss, and it
is written up in `docs/NOTEBOOK-MARKS.md` so the Phase 8 screenshot count does not read it as
one. Same precedent as Phase 3's `title-full`.

**MARK 2 — the margin note.** *Defence: it carries the open question or caveat behind the item
it sits next to.*

```scss
.entry {
  flex-wrap: wrap;
}

.entry-body {
  flex: 1 1 auto;
  min-width: 0;
}

.entry-note {
  position: relative;
  flex: 0 0 var(--note-col);
  font-size: var(--step-0);
  line-height: var(--leading-body);
  color: var(--ink-500);
}
```

Comment, and this is the load-bearing part: the note is an `<aside>` **sibling** of
`.entry-body`, never a nested absolutely-positioned element. With the stylesheet off,
`li.entry` is block flow and the three children stack — year, entry, note — so the note reads
as an ordinary sentence immediately after the item it annotates. GROUND-05 and criterion 3 are
then true **by construction** rather than by inspection. A flex row also grows to its tallest
child, so **two consecutive notes cannot overlap** — CONTEXT's open question, answered by
construction rather than tuned away.

`flex-wrap` is load-bearing, not polish: without it a fixed `--note-col` at a 390px viewport
produces horizontal overflow, which Phase 7 criterion 1 forbids and which would ship to a live
site in the meantime. It needs **no media query**, which keeps CONTEXT's "no breakpoint"
instinct intact and leaves Phase 5 free to formalise the ~768px collapse on top of it.

`min-width: 0` on `.entry-body` is also load-bearing: a flex item's default `min-width: auto`
refuses to shrink below its content, and a long unbroken title would otherwise push the note
out of the row.

**MARK 3 — the annotation bracket.** *Defence: it shows which item the note belongs to.*

```scss
.entry-note::before {
  content: "";
  position: absolute;
  left: calc(var(--space-3) * -1);
  top: var(--space-1);
  width: var(--space-2);
  height: var(--space-3);
  border-left: var(--rule-hairline) solid var(--rule-200);
  border-top: var(--rule-hairline) solid var(--rule-200);
}
```

Comment: **borders, never a glyph.** Screen readers announce generated text content, so a
bracket character in `content:` would be exactly the orphaned symbol criterion 3 forbids, and
hiding it again would need a second mechanism. `content: ""` has nothing to announce. Keep
`grep -rnE 'content:[[:space:]]*"[^"]+"' _sass/` empty. Colour is `--rule-200` (1.43:1) and
that is legitimate precisely because the bracket is meaningless on its own, so WCAG 1.4.11's
3:1 floor for graphical objects needed to understand content does not apply — argued in
`docs/NOTEBOOK-MARKS.md`, not assumed here. **No transition and no motion:** the gem's
`html.transition` class is only ever added by `theme.js`, which `enable_darkmode: false` drops
entirely, so the class never appears on this site and the bracket cannot inherit one. Do not
add one.

**MARK 4 — the link underline.** Already shipped in Phase 2 on `.post article a`. Add a
comment only, pointing at the existing rule and at `docs/NOTEBOOK-MARKS.md`, so the vocabulary
is complete in this file. **Change none of its values** — `--underline-thickness` and
`--underline-offset` are out of scope, and harness row 30 will catch a change.
