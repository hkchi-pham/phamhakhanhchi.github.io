  <action>
Create `.planning/tools/fontbudget.js` — a zero-dependency Node script (no npm install, no
`package.json` change) that mirrors `.planning/tools/contrast.js` in shape and spirit: a
criterion whose evidence cannot be re-run is a criterion nobody can regress-check.

Behaviour:

1. `node .planning/tools/fontbudget.js "<google fonts css url>" --max 153600`
   - Fetch the CSS with `https.get` sending
     `User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36`.
     **This is load-bearing.** Without a browser UA Google returns unsubsetted TrueType
     with no `unicode-range` and no `/* subset */` comments at all — from BOTH the v1
     and v2 endpoints (03-RESEARCH Finding 1). Bake the UA in as a constant; do not
     make it an optional flag anyone can forget.
   - Parse the response into `/* <subset> */` blocks. Keep only `latin` and
     `vietnamese` blocks. Extract each block's `url(...)` ending `.woff2`.
   - De-duplicate URLs (Literata 400 and 600 resolve to the SAME variable file — counting
     it twice overstates the payload by ~48 KB).
   - Download each unique URL, count the bytes actually received (do not trust
     `content-length` alone; sum the response stream and cross-check).
   - Print a table: family (from the block's preceding `font-family`), subset, URL tail,
     bytes. Then `TOTAL: <n> B (<n/1024> KiB, <n/1000> kB)`.
   - Print `BUDGET: <max> B` and `USED: <pct>%`.
   - `process.exit(1)` if total > max; `0` otherwise.

2. `node .planning/tools/fontbudget.js "<url>" [more urls...] --report-only`
   - No budget, always exit 0. For each URL: report the CSS response's own byte count,
     then every `url(...)` reference it contains that ends in `.woff2` — resolved against
     the CSS URL — with its byte count. Label the total **"declared"**, and print a one
     line note that a browser fetches a subset/icon file only when a glyph in it actually
     renders, so declared >= fetched. This is the mode that records the icon payload
     separately, as CONTEXT requires ("record the figure anyway so it is visible").

3. `--selftest` — the `contrast.js` precedent. Assert the parser against a small inline
   fixture string (a two-block `/* latin */` + `/* vietnamese */` CSS snippet with a
   duplicate woff2 URL) and check it yields 2 blocks and 1 unique URL. Exit nonzero on
   mismatch. No network. This is what makes "the budget tool is correct" a check row
   rather than a claim.

Constraints: plain CommonJS, `require('https')` only. No `fetch` polyfill, no axios, no
package.json edit. Handle redirects (`302`) on `fonts.gstatic.com`. Set a 30s timeout per
request and fail loudly rather than reporting a low total.

Record in a header comment: the measured baseline of 2026-09-16 — **141,232 B over 8
files for the five locked cuts (Literata v40, Be Vietnam Pro v12)** — and that the figure
is pinned to those font versions, so a later re-run returning a different number means
Google reissued a family, not that the tool broke.
  </action>
  <verify>
    <automated>node .planning/tools/fontbudget.js --selftest &amp;&amp; node .planning/tools/fontbudget.js "https://fonts.googleapis.com/css2?family=Be+Vietnam+Pro:wght@400;600&amp;family=Literata:ital,wght@0,400;0,600;1,400&amp;display=swap" --max 153600</automated>
  </verify>
  <done>`--selftest` exits 0. The live run prints a per-file table, a TOTAL in bytes, and exits 0 against `--max 153600`. The printed total is within a few hundred bytes of 141,232 (Google may reissue; a wildly different number is a finding to record, not a failure to hide).</done>
