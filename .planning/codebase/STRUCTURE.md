## Directory Purposes

**`_pages/`:**
- Purpose: Main site pages rendered as top-level URLs
- Contains: Markdown files with YAML front matter specifying layout, permalink, title, navigation order
- Key files: 
  - `_pages/about.md` (homepage, `layout: about`, `permalink: /`)
  - `_pages/cv.md` (CV page, `layout: page`, `permalink: /cv/`)
  - `_pages/projects.md` (projects listing page)
  - `_pages/academics.md`, `_pages/research.md`, `_pages/activities.md`, `_pages/further-reading.md`
- Rendered as: Direct URLs (e.g., `about.md` with `permalink: /` → `/`, `cv.md` → `/cv/`)

**`_projects/`:**
- Purpose: Individual project showcase entries (cards rendered on projects page)
- Contains: Markdown files with metadata (title, year, description, GitHub link, image, etc.)
- Key files: `_projects/friendship-web-game.md`, `_projects/soul-garden.md`
- Pattern: Each project front matter optionally includes `img`, `github`, `redirect`, `importance` fields
- Rendered as: Masonry grid on `/projects/` page (layout handles aggregation via site.projects)

**`_bibliography/`:**
- Purpose: BibTeX files for publications (processed by jekyll-scholar)
- Contains: `.bib` files (bibliographic database)
- Configured in `_config.yml`: `scholar: source: /_bibliography/, bibliography: papers.bib`
- Rendering: `jekyll-scholar` generates publication pages under `bibliography/` with badges (Altmetric, Dimensions, Google Scholar)

**`_posts/`, `_books/`, `_news/`, `_teachings/`:**
- Purpose: Additional Jekyll collections (template defaults)
- Status: Currently empty on this site — these collections are disabled in site configuration
- Usage: If re-enabled, follow same pattern as `_projects/` — markdown files → collection pages

**`_data/`:**
- Purpose: YAML files for structured data used throughout site
- Key files:
  - `_data/academics.yml` — Academic background, courses, schools, GPA
  - `_data/activities.yml` — Activities, clubs, leadership roles, dates
  - `_data/research.yml` — Research interests, publications, keywords
  - `_data/further_reading.yml` — Recommended reading, books, articles
  - `_data/socials.yml` — Social media profiles (linked in footer/navbar)
- Usage: Accessed in templates as `site.data.academics`, `site.data.activities`, etc.
- Rendering: Data-driven layouts render these as structured entry lists with years, titles, metadata

**`assets/`:**
- Purpose: Static files (images, CSS, JS, JSON, PDFs, Jupyter notebooks, etc.)
- Subdirectories:
  - `assets/css/` — Compiled CSS (`main.scss` entry point); override of gem-owned file
  - `assets/img/` — Images for page content, project covers, publication previews
  - `assets/pdf/` — PDFs (CV, papers, etc.)
  - `assets/json/` — JSON data (e.g., `resume.json` for CV rendering)
  - `assets/jupyter/` — Jupyter notebooks
  - `assets/html/` — HTML snippets
  - `assets/rendercv/` — RenderCV output (CV templates)
  - `assets/plotly/`, `assets/video/`, `assets/audio/`, `assets/bibliography/` — Feature-specific assets
- Build process: Images optimized with ImageMagick (if `imagemagick.enabled: true`); CSS compiled from Sass via `assets/css/main.scss`

**`bin/`:**

- Key files:

  - `bin/deploy` — Manual deployment to `gh-pages` branch (CI normally deploys)

## Naming Conventions

**Files:**
- Collections: `_name/` (underscore prefix, plural, snake_case) — e.g., `_pages/`, `_projects/`, `_bibliography/`
- Content: `slug.md` (kebab-case) — e.g., `about.md`, `friendship-web-game.md`
- Sass: `_partial.scss` (underscore prefix for partials, not compiled standalone) — e.g., `_custom.scss`, `_variables.scss`
- Scripts: kebab-case — e.g., `setup-python-deps`, `update_scholar_citations.py`
- Directories: kebab-case or snake_case — e.g., `assets/`, `_bibliography/`, `further-reading.yml`

**Repo Directories vs. Gem IDs:**
- GitHub repo names: kebab-case (e.g., `al-folio-core`, `al-search`, `al-folio-distill`)
- Gem/plugin IDs: snake_case (e.g., `al_folio_core`, `al_search`, `al_folio_distill`)
- Always use underscores in `Gemfile` and `_config.yml` `plugins:` list
- This distinction prevents silent failures when a mismatched name goes unnoticed

**YAML Front Matter Conventions:**
- Required: `layout`, `title` (or used for site title if omitted)
- Pages: `layout`, `title`, `permalink`, `nav` (boolean), `nav_order` (integer)
- Projects: `layout`, `title`, `description`, `year`, `importance`, optional: `img`, `github`, `redirect`
- Data-driven: `selected_papers`, `social`, `announcements: enabled:`, etc.

## Where to Add New Code

**New Page (e.g., /skills/, /blog/):**
- Location: `_pages/skills.md`
- Pattern:
  ```yaml
  ---
  layout: page
  title: Skills
  permalink: /skills/
  nav: true
  nav_order: 5
  ---
  ```
- Rendered as: Direct URL `/skills/`; nav link added if `nav: true` and `nav_order` set

**New Project Card:**
- Location: `_projects/project-name.md`
- Pattern:
  ```yaml
  ---
  layout: page
  title: My Project
  description: One-line description
  year: 2026
  importance: 1
  img: assets/img/project-cover.jpg
  github: https://github.com/...
  ---
  ```
- Rendered as: Card in masonry grid on `/projects/` page

**New Data File (for structured content):**
- Location: `_data/new_collection.yml`
- Pattern: YAML array of objects (dates, titles, metadata) — see `_data/academics.yml` for example
- Usage: Access in layouts as `site.data.new_collection`
- Rendered by: Data-driven layout in `_pages/` that loops over `site.data.new_collection`

**New Sass Override:**
- Location: `_sass/_custom.scss`
- Pattern: Add styles at bottom of file; they're imported last, so they override gem styles
- Tracking: After editing, run `bundle exec al-folio upgrade overrides audit` to update `.al-folio-overrides.yml`
- Scope: Keep overrides minimal; a full design pass should be in a customized theme

**New Gem Feature:**
- Do NOT add here; route to owning gem under `al-org-dev`
- Exception: If feature has no existing owner, open plugin proposal issue first

**Tests for This Repo:**
- Location: `test/integration_new_feature.sh` (shell script) or `test/visual/` (Playwright snapshots)
- Pattern: Follow existing `test/integration_*.sh` structure
- CI gate: Add to `.github/workflows/unit-tests.yml`

## Build and Serve

**Development Serve:**
```bash
bundle install          # Install Ruby gem dependencies
npm ci                  # Install Node dependencies
bundle exec jekyll serve  # Serve at http://localhost:4000/
```

**Production Build:**
```bash
bundle exec jekyll build  # Build to _site/
```

**Docker Serve:**
```bash
docker compose up -d           # Start container
curl http://127.0.0.1:8080/  # Verify
docker compose logs --tail=80  # View logs
docker compose down            # Stop
```

**Key Config:**
- `_config.yml` line 23: `baseurl:` is **empty** — this site serves from the root of the custom domain `phamhakhanhchi.com` (see `CNAME`). Never pass `--baseurl /al-folio` here.
- `_config.yml` line 106: `max_width: 930px` (layout container width)
- `_config.yml` line 254: `theme: al_folio_core` (sets theme to gem; local files can override)

## Stop Sign: Paths That Must NOT Exist Here

**Strictly forbidden by `npm run lint:style-contract`:**
- `_layouts/` — All layouts come from gems
- `_includes/` — All includes come from gems
- `_sass/` — This exists but only as override hook; must be minimal
- `_scripts/` — No local JS build pipeline
- `assets/tailwind/` — Tailwind ships prebuilt in gem
- `tailwind.config.js` — Tailwind configured in gem
- `assets/webfonts/`, icon font artifacts — All icons come from gem

**Exception:** This repo is the template; users' personal sites may legally shadow these (see ARCHITECTURE.md local overrides section). The `style-contract` check is enforced here to maintain thin-starter boundary.
